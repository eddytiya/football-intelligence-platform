# Matchday features

- `/prediction-tracker`: browser-local archive of the earliest valid saved forecast for each fixture. Current probabilities are never regenerated for scoring. Accuracy, multiclass natural-log loss, draw recall/precision, league breakdown, model filters, final scores and CSV export use reconciled API results. Only completed, past-kickoff fixtures with valid scores and pre-kickoff save times qualify. Exact probability ties use home/draw/away order. Zero probabilities are clipped at 1e-15 for log loss.
- `/compare?first=<team-id>&second=<team-id>`: searchable club selectors, swap, stored recent form/goals, head-to-head, linked results and the actual upcoming meeting's forecast when available. No probabilities are invented for arbitrary club pairs. Colour crests remain here.
- Calendar export: the Matches list exports displayed upcoming fixtures after its filters; individual Matches cards and dedicated match pages export one fixture. RFC 5545 `.ics` uses UTC, stable fixture UIDs, escaped text and UTF-8 line folding. It is a one-time import, not a subscribed calendar. No duration or venue is invented.
- Only Matches date-group cards opt into the new large broadcast-crest treatment. Eight explicitly mapped clubs have reviewed monochrome SVGs; others retain their original colour crest. Existing dashboard, auth and match-centre treatments are unchanged. The source illustration is a reference, not an SVG traced from generated club lettering.

The archive key is `football-forecast-archive`. Existing `prediction-history` records migrate if timestamps/probabilities are valid. The recent-history limit/Clear button does not truncate this archive. Clearing browser site data does remove it; account sync and independent tamper-proof timestamps are not provided. The tracker is a personal observed sample, not the entire model's performance. It cannot reconstruct forecasts that were never saved before kickoff.

The only backend changes add team IDs to existing profile fixture payloads and correct head-to-head attribution when the selected club also has historical alias rows. Prediction/model behaviour is unchanged.

## Home-ground backgrounds

Matches fixture cards select locally hosted Wikimedia Commons photos through exact home-club aliases in `src/utils/stadiumPhotos.js` and `stadiumPhotos.json`. Coverage: 26 stadiums / 27 clubs, including Monza's Stadio Brianteo and Parma's Stadio Ennio Tardini. AC Milan and Inter share San Siro. The photo never comes from the away club. Unknown clubs and image load failures show a neutral forest surface with an unavailable label, not the previous generic stadium.

Photographs are decorative home-ground context, can be archival and do not assert the actual venue for a particular fixture. Each card links to `public/images/stadiums/credits.html`, recording author, licence, original source, source photo date and CSS crop/overlay treatment. Complete provenance is in the neighbouring `sources.json` and embedded in each image. Preparation script: `.impeccable/prepare_stadium_assets.py`. The runtime makes no Wikimedia requests, needs no paid key and lazy-loads the local photos. Other page backgrounds are unchanged.

Validation: `npm run build`, `npm run lint`, `node --test tests/fan-features.test.js`; backend regression `backend/tests/unit/test_team_comparison_aliases.py`. Build/lint succeed with the existing bundle-size advisory and eight hook dependency warnings. Isolated desktop/mobile browser checks verify actual SVG loading, colour crests outside Matches, comparison swap, real-fixture calendar download, tracker league filtering and CSV export. Filled tracker QA screenshots explicitly use synthetic controlled data; those are not performance claims. Evidence: `.impeccable/review/fan-features/` in the project root.
