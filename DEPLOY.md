# Deploying for free

Three free services, wired together:

| Piece | Service | Why |
|---|---|---|
| Database | [Neon](https://neon.tech) | Free serverless Postgres that doesn't expire (Render's free Postgres auto-deletes after 90 days) |
| Backend (FastAPI) | [Render](https://render.com) | Free web service, deploys straight from GitHub via `render.yaml` |
| Frontend (React/Vite) | [Vercel](https://vercel.com) | Free static hosting, deploys straight from GitHub |

Account creation and clicking "Deploy" have to happen in your own browser — sign up with GitHub on
each so deploys can auto-trigger on push. Everything below is the exact config already in this repo;
you're just filling in the account-specific values.

## 1. Push this repo to GitHub

The two oversized model files (`random_forest.joblib`, `extra_trees.joblib`) are now gitignored —
they're training artifacts only; the app serves predictions from `best_model.joblib` alone, which is
already tracked. Commit and push the prep changes, then continue.

```bash
git add -A
git commit -m "Prepare repo for free hosting (Render + Vercel + Neon)"
git push
```

## 2. Database — Neon

1. Sign up at neon.tech (free), create a project.
2. Open the project's **Connection Details**. You'll get a string like:
   `postgresql://neondb_owner:AbC123@ep-cool-thing-12345.us-east-2.aws.neon.tech/neondb?sslmode=require`
3. Split that into the values Render will need:
   - `DB_HOST` = `ep-cool-thing-12345.us-east-2.aws.neon.tech`
   - `DB_PORT` = `5432`
   - `DB_NAME` = `neondb`
   - `DB_USER` = `neondb_owner`
   - `DB_PASSWORD` = the password shown
   - `DB_SSLMODE` = `require` (already set in `render.yaml`)

## 3. Backend — Render

1. Sign up at render.com with GitHub, authorize access to this repo.
2. **New → Blueprint**, pick this repo. Render reads [`render.yaml`](render.yaml) and proposes the
   `football-intelligence-api` web service on the free plan automatically.
3. Before the first deploy, fill in the env vars marked `sync: false` in the Render dashboard:
   - `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` — from Neon, step 2.
   - `FOOTBALL_API_KEY` — free key from https://www.football-data.org/client/register.
   - `CORS_ORIGINS` — leave as `http://localhost:5173` for now; you'll update it in step 5 once you
     have the Vercel URL.
   - `AUTH_SECRET_KEY` is auto-generated by the blueprint — leave it.
4. Deploy. The build runs `pip install -r requirements.txt && alembic upgrade head`, so the database
   schema is created automatically on first deploy. Note the service URL Render gives you, e.g.
   `https://football-intelligence-api.onrender.com`.

**Free-tier tradeoff:** the free web service sleeps after 15 minutes with no traffic (cold start on
the next request takes 30-50s), and the in-process live-score/notification sync loops pause while
asleep — they resume automatically once a request wakes the service. If you want the sync loops to
keep running continuously, a free external pinger like [cron-job.org](https://cron-job.org) hitting
`https://<your-render-url>/` every 10 minutes keeps it awake. Not required to have a working site.

## 4. Frontend — Vercel

1. Sign up at vercel.com with GitHub, **Add New → Project**, pick this repo.
2. Set **Root Directory** to `frontend`. Vercel auto-detects Vite (`npm run build`, output `dist`).
3. Add an environment variable: `VITE_API_BASE_URL` = your Render URL from step 3
   (e.g. `https://football-intelligence-api.onrender.com`, no trailing slash).
4. Deploy. [`frontend/vercel.json`](frontend/vercel.json) is already set up so client-side routes
   (React Router) don't 404 on refresh.

## 5. Close the loop: CORS

Back in Render, set `CORS_ORIGINS` to your Vercel URL (e.g. `https://football-intelligence-platform.vercel.app`)
— comma-separate if you also want to allow a custom domain later — and redeploy the backend so it accepts
requests from the deployed frontend.

## After that

### Administrator access

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` (at least 16 characters) in the Render
service environment, then redeploy. Startup creates the account with a hashed
password and grants the administrator role. Existing accounts are promoted only
when their password matches; their passwords are never reset automatically.
Sign in at `/login` and open `/admin/predictions` on the frontend.

For local access, credentials can be kept in the gitignored root `.env.access`.
Run `backend/.venv/Scripts/python.exe backend/scripts/setup_prediction_admin.py`
from the repository root to provision that account against the configured backend
database. Keep this file private and never copy its secrets into frontend env vars.

- Every `git push` to the deployed branch auto-redeploys both Render and Vercel.
- Keep real secrets (`.env`, API keys, DB password) only in the Render/Neon dashboards — never commit them.
- `NEWS_API_KEY` and `NOTIFICATIONS_EMAIL_ENABLED`/SMTP vars are optional; the app works without them.
